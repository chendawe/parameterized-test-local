路由：
你是一个智能请求路由助手，你的唯一任务是分析用户输入的意图，并输出结构化的路由指令（仅输出JSON，无其他文字）。

## 意图分类规则
你需要将用户输入归类到以下3种意图之一：
1. KNOWLEDGE_QA：用户询问专业领域知识（如LLM量化原理、RAG流程、HNSW索引等），需要调用RAG增强的LLM回答；
2. TOOL_CALL：用户需要调用外部工具（如查询数据库、生成报告、计算数据、查询天气等），需要触发Function Call；
3. CHITCHAT：用户无明确专业需求，仅闲聊/寒暄（如“你好”“随便聊聊”“今天天气不错”），直接用基础LLM回复。

## 输出格式要求
必须严格按照以下JSON格式输出，字段不可增删，意图值只能是KNOWLEDGE_QA/TOOL_CALL/CHITCHAT中的一个：
{
  "intent": "意图类型",
  "confidence": 0.0-1.0（表示你对意图分类的置信度）,
  "keywords": ["提取的核心关键词，数组格式"]
}

6. 为什么用了个路由agent？采用的提示词是什么？
    - 问题背景：用户的提问意图多样，有些是纯知识问答，有些是需要调用外部工具（如查询数据库、生成报告），有些则是闲聊。单一的 LLM 无法高效处理所有场景。
    - Agent 作用：路由 Agent 就像一个 “交通指挥员”，通过对用户输入的语义分析，动态决定将请求路由到哪个子模块：
        - 知识问答 → RAG 增强的 LLM。
        - 工具调用 → 触发特定的 Function Call。
        - 闲聊 → 直接由基础 LLM 回复。
    - 实现方式：通过精心设计的提示词工程，让 LLM 输出结构化的路由指令（如 JSON 格式），后端解析后执行相应逻辑。这避免了为每个场景单独训练模型，提升了系统的灵活性和可扩展性。

7. 为什么选择FastAPI+Uvicorn？宝塔面板干了哪些事情？

4. 怎么理解MCP？
    - 核心理念：
        - 解耦：将一个复杂的任务（如 “安排下周的会议并发送邮件通知”）拆解成多个原子化的智能体，每个智能体只负责一个专业领域（如 “日程智能体”、“邮件智能体”）。
        - 协作：通过一个中央协调器（或智能体之间的通信协议），让这些专业智能体根据任务流，有序地交换信息、接力完成任务。
    - 我的实践：在这个项目中，我用 LangGraph 定义了一个状态机，意图识别模型作为入口，根据输出的标签，将任务流转到对应的智能体节点，执行完成后再将结果汇总返回给用户。这大大提升了系统的模块化程度和可维护性。

5. langsmith的使用经验？
    - 核心用途：Langsmith 是一个用于 LLM 应用开发和运维的全生命周期平台。我计划用它来解决以下问题：
        - 追踪与调试：可视化智能体的执行轨迹，查看每个节点的输入输出、耗时和错误，快速定位 “卡壳” 的环节。
        - 性能监控：监控 LLM 的调用次数、token 消耗、延迟和错误率，生成成本和性能报表。
        - 数据集管理：管理测试用例，对比不同版本 Prompt 和模型的表现，进行 A/B 测试。
        - 部署与迭代：将经过验证的智能体工作流一键部署到生产环境，并支持灰度发布和快速回滚。
    - 预期价值：它能让我从 “黑盒式” 的智能体开发，转变为 “可观测、可复现、可迭代” 的工程化开发，提升整个项目的可靠性和效率。

参数名	核心作用	推荐值（中文场景）	调整原则
r（rank）	低秩矩阵的秩，控制更新量	8/16	小任务（如 10 类意图分类）用 8，复杂任务（如多轮对话）用 16；r 越大越接近全量微调，但显存占用越高
lora_alpha	缩放因子	16/32	通常设为 2*r，平衡梯度更新幅度
lora_dropout	Dropout 概率	0.05/0.1	数据集小（<1 万条）用 0.1（防止过拟合），数据集大（>10 万条）用 0.05
bias	是否微调偏置项	"none"	几乎不用微调偏置项，"none" 可减少计算量，"all" 会大幅增加显存占用
task_type	任务类型	"SEQ_CLASSIFICATION"/"CAUSAL_LM"	分类任务用 SEQ_CLASSIFICATION，生成任务用 CAUSAL_LM
learning_rate	学习率	1e-4（335M 模型）/5e-5（7B 模型）	LLM 学习率需更小，避免过拟合；可配合余弦退火调度器（cosine annealing）
batch_size	批次大小	8/16（单卡）	按显存调整，RTX4060（8G）用 8，RTX4090（24G）用 16
num_train_epochs	训练轮数	3/5	小数据集（<1 万）训 5 轮，大数据集（>10 万）训 3 轮；结合早停（early stopping）
weight_decay	权重衰减	0.01	防止过拟合，固定值即可
